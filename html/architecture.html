ProLaptop Server

App chạy như thế nào, từ đầu đến cuối

Backend cho một cửa hàng laptop: khách đăng ký, xem sản phẩm, thêm vào giỏ, đặt hàng (tiền mặt hoặc ZaloPay), đánh giá và chat với admin. Viết bằng NestJS, lưu dữ liệu ở PostgreSQL qua TypeORM.

Nhìn từ xa

Request đi từ trên xuống: cửa vào → module → TypeORM → database. Nét đứt là server gọi dịch vụ bên ngoài.

Code nằm ở đâu

main.ts

Điểm bắt đầu. Tạo app, bật cấu hình chung, mở cổng 5003.

modules/

Mỗi thư mục là một tính năng: auth, cart, order…

entities/

Mỗi file là một bảng trong database.

common/

Đồ dùng chung: kết nối DB, enum, phân trang.

Khái niệm cốt lõi

Các khái niệm cốt lõi của NestJS

Sáu khái niệm dưới đây có mặt trong mọi file của project. Đọc theo thứ tự: mỗi khái niệm dựa trên khái niệm trước.

Modulecart.module.ts

Đơn vị tổ chức code. Mỗi tính năng là một module, khai báo nó có controller nào, provider nào, và cần mượn gì từ module khác (imports). Cả app là một cây module, gốc là AppModule.

@Module({
  imports: [
    TypeOrmModule.forFeature([Cart, Product]),
  ],
  controllers: [CartController],
  providers: [CartService],
})
Controllercart.controller.ts

Nhận HTTP request ở một URL và trả response. Controller chỉ đọc dữ liệu gửi lên rồi giao việc cho service. Không chứa logic nghiệp vụ, không truy vấn database.

// mọi URL /api/cart/...
@Controller('cart')
export class CartController { ... }
Providerproviders: [...]

Bất kỳ class nào Nest có thể tự tạo instance và tiêm vào class khác. Điều kiện: có @Injectable() và được khai báo trong providers của một module.

ServiceGuardStrategyGatewayRepository

Đều là provider. Service là loại hay gặp nhất.

Servicecart.service.ts

Một provider chứa logic nghiệp vụ: kiểm tra tồn kho, tính tiền, đọc và ghi database, gọi dịch vụ ngoài. Controller gọi service; service có thể gọi service khác.

@Injectable()
export class CartService { ... }
DI & IoC Containerconstructor(...)

Dependency Injection: class không tự new thứ nó cần, chỉ liệt kê trong constructor. IoC Container là bộ phận của Nest tạo instance cho mọi provider lúc khởi động, giữ lại, rồi tiêm vào nơi cần.

constructor(private cartService: CartService) {}
// không có "new CartService()" ở đâu cả
Decorator@Something

Nhãn bắt đầu bằng @ dán lên class, hàm hoặc tham số. Nó không tự chạy logic; nó cho Nest biết thứ đó dùng vào việc gì. Mọi khái niệm ở trên đều được khai báo bằng decorator.

@Module@Controller@Injectable@Get@Post@Body@Param@UseGuards

IoC Container tạo instance như thế nào

Lúc khởi động, container đọc providers của mọi module, nhìn constructor để biết mỗi class cần gì, tạo thứ được cần trước rồi mới tạo class cần nó. Mỗi instance được tạo một lần và dùng chung tới khi app tắt.

① tạo trước
Repository<Cart>do TypeOrmModule.forFeature đăng ký
Repository<Product>đọc tồn kho
→
② tiêm vào
CartServicenew CartService(cartRepo, productRepo)
→
③ tiêm tiếp vào

Các dòng new … ở trên là việc container tự làm. Trong code của bạn không có dòng nào như vậy.

Cấu trúc một Controller

@Controller('cart')1
export class CartController {
  constructor(private readonly cartService: CartService) {}2

  @Post()3
  async addToCart(@Body() createCartDto: CreateCartDto) {4
    return await this.cartService.create(createCartDto);5
  }

  @Get(':id')3
  async findOneById(@Param('id') id: string) {4
    return this.cartService.findOneById(id);5
  }
}
  1. 1
    Đường dẫn gốc. Mọi route trong class bắt đầu bằng /api/cart.
  2. 2
    Nhận service qua DI. Container tiêm CartService vào.
  3. 3
    Method + đường dẫn con. @Post() = POST /api/cart, @Get(':id') = GET /api/cart/123.
  4. 4
    Lấy dữ liệu từ request. @Body() lấy body, @Param('id') lấy phần :id trên URL, @Query() lấy ?page=1.
  5. 5
    Giao việc cho service và trả kết quả. Nest tự đổi object thành JSON.

Rút gọn từ src/modules/cart/cart.controller.ts.

Cấu trúc một Service

@Injectable()1
export class CartService {
  constructor(
    @InjectRepository(Cart) private cartRepo: Repository<Cart>,2
    @InjectRepository(Product) private productRepo: Repository<Product>,
  ) {}

  async create(dto: CreateCartDto) {
    const product = await this.productRepo
      .findOne({ where: { id: dto.productId } });3
    if (!product)
      throw new NotFoundException('Product not found');4
    if (dto.quantity > product.stockQuantity)
      throw new BadRequestException(...);

    const item = this.cartRepo.create(dto);5
    await this.cartRepo.save(item);
    return { message: 'Added to cart', cart: item };6
  }
}
  1. 1
    Đánh dấu là provider để container tạo và tiêm được.
  2. 2
    Nhận Repository qua DI. Repository là công cụ của TypeORM để đọc/ghi một bảng.
  3. 3
    Đọc database. TypeORM đổi thành SELECT … FROM product WHERE id = ….
  4. 4
    Kiểm tra nghiệp vụ. Ném exception là đủ; Nest tự trả 404 / 400 dạng JSON.
  5. 5
    Ghi database. create() chỉ tạo object, save() mới INSERT.
  6. 6
    Trả kết quả về controller.

Rút gọn từ src/modules/cart/cart.service.ts.

Request Lifecycle

Trước khi tới Controller, request đi qua các lớp theo thứ tự cố định. Đây là Request Lifecycle của NestJS. Mỗi lớp có một màu, dùng lại ở các sơ đồ bên dưới.

Middlewarechuẩn bị chung cho mọi request
Guardcó được vào không?
Interceptorxử lý trước / sau handler
Pipevalidate và ép kiểu dữ liệu
Controllerroute handler
Servicelogic nghiệp vụ
Databasequa TypeORM

Mỗi lớp nằm ở file nào trong project

LớpĐược viết ởĐược gắn vào route ở
Middlewaremain.ts: enableCors, app.use(session(...)), passport.initialize()Tự áp dụng cho mọi request
Guardmodules/auth/utils/auth.guard.ts → AuthGuard (kiểm tra JWT)
modules/auth/utils/role.middleware.ts → RolesGuard (kiểm tra role; tên file là middleware nhưng là guard)
modules/auth/utils/google.guard.ts → GoogleAuthGuard		@UseGuards(...) trong order.controller.ts, zaloPayment.controller.ts, auth.controller.ts
InterceptorFileInterceptor có sẵn của @nestjs/platform-express@UseInterceptors(FileInterceptor('avatar')) trong user, category, product controller
PipeValidationPipe bật toàn cục ở main.ts; luật kiểm tra nằm trong dto/*.dto.ts (@IsNotEmpty()…)Tự áp dụng cho tham số có kiểu DTO, ví dụ @Body() dto: CreateCartDto
Controllermodules/*/xxx.controller.tsKhai báo trong controllers của module
Servicemodules/*/xxx.service.tsKhai báo trong providers của module
Exception filterDùng filter mặc định của Nest, không có file riêngBắt mọi exception, ví dụ NotFoundException → JSON 404

Ví dụ: gắn Guard vào một route

// src/modules/order/order.controller.ts
@Post('/create-from-cart/')
@UseGuards(AuthGuard, new RolesGuard([RoleEnum.USER, RoleEnum.ADMIN]))1
async createOrderFromCart(@Req() request, @Body() body) { ... }
  1. 1
    Guard chạy từ trái sang phải. AuthGuard kiểm tra token và gán thông tin user vào request.user; RolesGuard đọc request.user.role. Thiếu token → 401, sai role → 403, controller không được gọi.

Vòng đời request

Một request đi qua những đâu

Chọn một ví dụ để xem request đi qua những lớp nào của Request Lifecycle. Lớp sáng là lớp request đi qua, lớp mờ là lớp bị bỏ qua.

    Phần lớn route không có Guard, nên chỉ đi Middleware → Pipe → Controller → Service → Database. Chỉ các route cần đăng nhập (đặt hàng, xem đơn, thanh toán) mới có Guard kiểm tra token.

    Database

    ERD: 8 bảng và cách chúng nối với nhau

    Mỗi hộp là một bảng, chỉ hiện các cột quan trọng. FK (khoá ngoại) là cột trỏ sang bảng khác.

    một nhiều Mọi bảng (trừ message) còn có createdAt, updatedAt, deletedAt

    Đọc sơ đồ

    • Một user có nhiều dòng cart và nhiều orders.
    • Một orders gồm nhiều order_detail; mỗi dòng là một sản phẩm, lưu giá tại lúc mua.
    • Mỗi order_detail được đánh giá tối đa một lần bằng một review.
    • Xoá dữ liệu là xoá mềm: không xoá dòng, chỉ ghi thời điểm vào deletedAt; TypeORM tự bỏ qua các dòng này khi đọc.
